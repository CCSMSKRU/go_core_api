### Системный промпт для создания интерактивного скрипта тестирования

Твоя задача — разработать интерактивный скрипт на Node.js для тестирования библиотеки `go_core_api`. Этот скрипт должен позволять пользователю проверять работу библиотеки в режимах AJAX и WebSocket, имитируя различные сетевые состояния (отключение сервера, ожидание восстановления).

#### ТРЕБОВАНИЯ К СКРИПТУ:

1.  **Конфигурация и подготовка:**
    *   При запуске скрипт должен проверять наличие файла `.env`. Если он отсутствует, скрипт должен создать его, скопировав содержимое из `.env.example`.
    *   Скрипт должен вывести инструкцию пользователю о необходимости заполнить `.env` корректными данными и дождаться подтверждения (Enter) перед продолжением.
    *   Скрипт должен вывести инструкцию о необходимости выполнить сборку библиотеки (`npm run build`) и дождаться подтверждения (Enter) от пользователя.
    *   Параметры подключения (host, port, https), режим `autoAuth`, логин и пароль должны загружаться из файла `.env`.
    *   Предусмотри использование библиотеки `dotenv` или простой парсинг `.env` файла.

2.  **Интерактивность:**
    *   Скрипт должен взаимодействовать с пользователем через консоль (используй `readline`).
    *   Скрипт должен давать четкие инструкции пользователю: когда включить сервер, когда выключить, когда сбросить сессию на сервере.
    *   Скрипт должен ждать подтверждения от пользователя (нажатие Enter) перед переходом к следующему шагу теста.

3.  **Тестирование режимов (AJAX и WebSocket):**
    *   Проверка инициализации с `useAJAX: true` и `useAJAX: false`.
    *   Имитация ожидания авторизации: запуск запроса при выключенном сервере.
    *   Проверка успешного завершения запроса после включения сервера (с учетом параметров `tryAuthCount` и `tryAuthPause`).
    *   Проверка автоматического восстановления (reconnect) для WebSocket: пользователь включает сервер, скрипт ожидает некоторое время и выполняет успешный запрос без ручной переинициализации.

4.  **Тестирование функционала API:**
    *   Выполнение запроса `User.getMe`.
    *   Выполнение запросов `User.login` и `User.logout`.
    *   **Тест события `logout` от сервера:** Скрипт должен просить пользователя принудительно завершить (убить) сессию на сервере. При получении события `logout` библиотека должна автоматически инициировать процесс повторной авторизации (если `autoAuth: true`).

5.  **Технические детали:**
    *   Скрипт должен располагаться в папке `tests/interactive_test.js`.
    *   Скрипт должен импортировать библиотеку из `dist/index.js`.
    *   **Важно:** Учитывай, что библиотека может быть собрана как UMD-модуль для браузера и может обращаться к глобальным объектам `window`, `document`, `navigator`, `location`, `localStorage`. При запуске в Node.js необходимо эмулировать эти объекты перед импортом библиотеки.
    *   Пример эмуляции:
        ```javascript
        global.self = global;
        global.window = global;
        global.document = { 
            cookie: '', 
            createElement: () => ({ setAttribute: () => {}, style: {}, appendChild: () => {} }),
            getElementsByTagName: () => [],
            documentElement: { style: {} },
            body: { appendChild: () => {} },
            addEventListener: () => {},
            removeEventListener: () => {}
        };
        global.navigator = { userAgent: 'node.js' };
        global.location = { protocol: 'http:', host: 'localhost', hostname: 'localhost', href: 'http://localhost/' };
        global.localStorage = { 
            _data: {}, 
            setItem: (k, v) => { this._data[k] = String(v); }, 
            getItem: (k) => this._data[k] || null 
        };
        ```
    *   Использование логирования с цветовым выделением шагов (ANSI escape codes) приветствуется.

6.  **Выбор среды (Браузер / Node.js):**
    *   Скрипт должен предлагать пользователю выбрать среду выполнения:
        1. **Браузер (Browser):** эмуляция глобальных объектов браузера (window, document и др.). Полезно для тестирования UMD-бандла, предназначенного для фронтенда.
        2. **Node.js:** нативное окружение без эмуляции браузерных API. Полезно для тестирования использования библиотеки в серверных приложениях (связь сервер-сервер).
    *   В зависимости от выбора, скрипт должен просить пользователя выполнить соответствующую сборку (`npm run build` для браузера или `npm run buildNode` для Node.js).

7.  **Структура выполнения:**
    *   Скрипт должен предлагать выбор режима тестирования или конкретного сценария при запуске.
